# 回页｜产品定位

> 当前共识：2026-07-24

> 在线入口：[打开回页](https://huiye-ai-diary.zhenghengchen13.chatgpt.site)（仅限已授权的 OpenAI 账号访问）

> 文档导航：[完整索引](DOCUMENTATION_INDEX.md) · [阶段规划](ROADMAP.md) · [技术指南](TECHNICAL_GUIDE.md)

## 一句话

**回页存放当下的思考，并在未来某一天恰当地带回过去的思考，为用户提供延伸思考的可能。**

它的本质，是设计一段人与过去自我对话的系统，让它作用于明天。

## 要验证的核心假设

> 当过去的思考在恰当的时刻被带回来，用户会感到有用，并自然延申出新的思考。

成功不是 AI 生成得多漂亮，而是用户愿意打开旧记录、沿着它继续写，或据此修正今天的判断。

## 用户与问题

面向已经在记录、但思考散落在阅读笔记、即时文档、手写内容和临时记录中的人。

他们不缺保存工具；缺的是：

- 不先管理、分类、命名也能留下当下的真实思考；
- 在需要时重新进入当时的条件、犹豫和推理；
- 让新的经验能与过去的判断相遇，而非被新的内容覆盖。

## 核心体验

```text
写下当下
  → 安静保存「我的思考」
  → 后台建立候选关联
  → 在错位的回响，或主动的对话中带回证据
  → 用户打开、继续写，或判定无关
```

**保存是安静的；回响是错位的；对话是主动的。**

保存后不立即召回。写作时的注意力稀缺，回页不能抢走它。

## 三类记忆

### 原始记忆

用户当时真实写下的内容、时间、情境和犹豫。它是回页的核心燃料，永远不能被 AI 覆盖。

### 思考线

一篇旧记录被重新看见后，用户沿着它继续写形成的连接；也可包含 AI 提出、经用户认可的关联。它保留真实延伸过的轨迹，而非由 AI 单方面定义。

### 使用记忆

系统记得某段旧思考是否被带回、用户是否打开、是否继续写、是否判定无关。它帮助系统以后更聪明地沉默或出现。

## 三层产品结构

### 原料层

保存用户确认过的「我的思考」。日记池是原料的主要容器；AI Chat 是产生新思考的应用入口，整段对话不会自动成为原料。只有用户明确确认、保存的内容，才进入原料层。

### 记忆层

保存思考之间真实发生过的延伸，以及回响被使用的结果。必须区分 AI 猜测的候选关联、用户确认有用的关联，以及用户沿着旧思考继续写形成的思考线；三者的可信度不同。

### 应用层

通过被动回响、主动对话或其他入口，在需要时带回过去的证据。系统可以识别用户是在形成新思考、寻找过去线索，或两者同时发生；AI 可以提出候选草稿和问题，但不能未经确认替用户写入新的「我的思考」。

> 回页积累的核心资产不是文档，也不是 AI 对话，而是用户确认过的思考，以及这些思考真实延伸过的轨迹。

三层共同形成一个私密的个人思考连续性循环：用户写下第 N 篇思考，回响或对话带来启发，用户继续写出第 N+1 篇；新的思考线和使用信号再帮助系统判断未来何时出现、何时沉默。

> 技术上能实现，和一个人会不会持续使用，是两回事。专门产品的价值通常来自默认行为、低摩擦、节奏和克制，而不是别人绝对做不到。

## AI 的角色

AI 不替用户完成端到端思考，也不做人设分析、心理判断或人生结论。

AI 可以：

- 在允许关联的记录中寻找候选；
- 判断一段旧记录是否能提供旧假设、背景、反例、条件或未完成的问题；
- 带回可核对的原句、时间和轻量理由；
- 在对话中引用用户自己的证据并轻轻发问。

AI 整理不再作为当前产品功能与主线。标题、标签和“整理得更漂亮”都不是回页要验证的核心价值；回页先把注意力放在可靠保存、恰当带回与继续思考上。

## 回响的第一原则

- 默认只带回 1 篇旧记录；
- 必须展示原句与时间，理由必须可追溯；
- 不确定时保持空白；
- 用户可以打开看看、沿着它继续写、或标记这次无关；
- 不做保存后弹窗、每日推送或未读压力。

## 当前不做

- 人格分析、情绪诊断、自动人生总结；
- 复杂 Agent、知识图谱、用户画像；
- 高频被动提醒；
- 用标签和标题代替真正的关联；
- 多用户、社交和公开社区。

## 思考的单一版本

每一篇记录对用户而言只保留一份当前有效的「我的思考」。它可以是用户直接写下的内容，也可以是用户亲自修改、确认后的版本；系统不再把“原文 / AI 整理稿”作为日常使用中的双版本负担。

这不是放弃原始性，而是避免为了一个尚未验证价值的整理功能，制造更多需要用户理解和管理的状态。未来如果重新引入版本能力，也必须服务于“人与过去自我对话”，而不是服务于 AI 的整理展示。

## 数据归属与迁移

当前阶段，日记、草稿、回响反馈和设置都只保存在**当前设备、当前浏览器**的本地存储中；网址本身不等于数据同步。

用户必须能够带走自己的思考。因此导出不是一个附属按钮，而是本地优先策略的一部分。当前已经提供：

- Markdown 导出：可选择多篇，包含标题、时间、来源、正文和标签，便于阅读与归档；
- 完整 JSON 备份：包含思考、图片、关联许可、思考线、回响和回响检查记录；
- JSON 导入：替换当前浏览器中的日记与回响记录，恢复完整上下文。

换电脑时，应在旧电脑导出完整 JSON 备份，再在新电脑导入。Markdown 只用于阅读和归档，不能替代完整迁移。未保存的写作草稿不包含在完整备份中。
