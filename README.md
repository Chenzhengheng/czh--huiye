# 回页｜产品定位

> 当前共识：2026-08-01

> 当前使用方式：回页作为本地应用运行，私人数据只从项目的 `local-data` 文件夹读取和写入。

> 历史私人演示：[打开旧线上版本](https://huiye-ai-diary.zhenghengchen13.chatgpt.site)（仅用于迁移核对，不再作为本地主数据源）

> 求职展示：独立的公开作品集网站只使用脱敏演示内容，并链接代码仓库；它与私人日记应用分开发布。

> 文档导航：[完整索引](DOCUMENTATION_INDEX.md) · [阶段规划](ROADMAP.md) · [技术指南](TECHNICAL_GUIDE.md)

## 一句话

**回页保存当下的思考，并在过去与当下出现联系时提出一段可核对的回响，让用户继续写出新的思考。**

它的本质，是设计一段人与过去自我对话的系统，让它作用于明天。

## 要验证的核心假设

> 当回页发现用户尚未表达出来的判断变化，或让一段旧思考在恰当的时间重新进入当下时，用户会愿意继续写，并形成真实的思考延续。

成功不是 AI 生成得多漂亮，也不是用户点开了多少次，而是回响之后，用户真正保存了一篇新的思考。

## 用户与问题

面向已经在记录、但思考散落在阅读笔记、即时文档、手写内容和临时记录中的人。

他们不缺保存工具；缺的是：

- 不先管理、分类、命名也能留下当下的真实思考；
- 在需要时重新进入当时的条件、犹豫和推理；
- 让新的经验能与过去的判断相遇，而非被新的内容覆盖。

## 核心体验

```text
写下当下
  → 安静保存「我的思考」
  → 发现过去与当下的候选联系
  → 以原句和问题提出回响
  → 用户打开、拒绝或继续写
  → 保存后形成被验证的思考线
```

## 两类回响

### 关系延续：A + B → C

用户写下 B 后，系统发现它与过去的 A 存在判断变化、冲突或尚未被表达的联系。回响同时展示 A、B 的证据，邀请用户写下 C。系统只能提出“似乎存在变化”，不能替用户断言“你已经改变”。

### 时间延续：A + 现在 → B

一段旧思考经过一定时间后重新进入当下。回响展示 A 的时间和原句，邀请用户确认：变化是否符合预期、发生了什么、现在如何看。

两类场景可以重叠，但当前先分别判断。它们共同追求的不是把内容找回来，而是促成新的思考。

**保存是安静的；回响是错位的；对话是主动的。**

保存后不立即展示回响。写作时的注意力稀缺，回页不能抢走它。

## 三类记忆

### 原始记忆

用户当时真实写下的内容、时间、情境和犹豫。它是回页的核心燃料，永远不能被 AI 覆盖。

### 思考线

用户从一次关系回响或时间回响继续写，并真正保存新思考后形成的连接。关系延续记录 A + B → C，时间延续记录 A + 现在 → B；只有保存完成的延续才进入思考线。

### 使用记忆

系统记得某次回响是否被打开、被认为没有联系、暂时不合时机、开始继续写，以及是否最终保存。只有保存新思考是有效延续，其他行为是用于改善判断的过程信号。

## 三层产品结构

### 原料层

保存用户确认过的「我的思考」。日记池是原料的主要容器；AI Chat 是产生新思考的应用入口，整段对话不会自动成为原料。只有用户明确确认、保存的内容，才进入原料层。

### 记忆层

保存候选关联、回响交互日志，以及用户真正保存过的思考延续。必须区分系统提出的联系、用户对这次回响的反馈和已形成的新思考；三者的可信度不同。

### 应用层

通过关系回响、时间回响、主动对话或其他入口，让过去与当下相遇。系统可以指出候选联系、交还可核对的证据并轻轻发问，但不能替用户断言变化，也不能未经确认写入新的「我的思考」。

> 回页积累的核心资产不是文档，也不是 AI 对话，而是用户确认过的思考，以及这些思考真实延伸过的轨迹。

三层共同形成一个私密的个人思考连续性循环：用户写下第 N 篇思考，回响或对话带来启发，用户继续写出第 N+1 篇；新的思考线和使用信号再帮助系统判断未来何时出现、何时沉默。

> 技术上能实现，和一个人会不会持续使用，是两回事。专门产品的价值通常来自默认行为、低摩擦、节奏和克制，而不是别人绝对做不到。

## AI 的角色

AI 不替用户完成端到端思考，也不做人设分析、心理判断或人生结论。

AI 可以：

- 在参与未来回响的记录中寻找候选联系；
- 判断过去与当下之间是否存在值得用户重新思考的变化、冲突、条件或时间问题；
- 展示可核对的原句、时间和轻量理由，不把推测写成用户结论；
- 在对话中引用用户自己的证据并轻轻发问。

AI 整理不再作为当前产品功能与主线。标题、标签和“整理得更漂亮”都不是回页要验证的核心价值；回页先把注意力放在可靠保存、恰当带回与继续思考上。

## 回响的第一原则

- 一次只提出 1 个值得停留的联系；
- 关系延续必须展示 A、B 的原句与时间；时间延续必须展示 A 的原句、时间和“为什么是现在”；
- 不确定时保持空白；
- 用户可以打开看看、继续写、标记没有联系，或说明现在还不是时候；
- 不做保存后弹窗、每日推送或未读压力。

## 当前不做

- 人格分析、情绪诊断、自动人生总结；
- 复杂 Agent、知识图谱、用户画像；
- 高频被动提醒；
- 用标签和标题代替真正的关联；
- 多用户、社交和公开社区。

## 思考的单一版本

每一篇记录对用户而言只保留一份当前有效的「我的思考」。它可以是用户直接写下的内容，也可以是用户亲自修改、确认后的版本；系统不再把“原文 / AI 整理稿”作为日常使用中的双版本负担。

这不是放弃原始性，而是避免为了一个尚未验证价值的整理功能，制造更多需要用户理解和管理的状态。未来如果重新引入版本能力，也必须服务于“人与过去自我对话”，而不是服务于 AI 的整理展示。

## 数据归属与迁移

回页采用本地优先架构。日记、图片、思考线和回响反馈保存在用户明确拥有的 `local-data` 文件夹中；本地应用只负责读取、校验和写回这个文件夹。线上作品集不读取私人目录，也不保存真实日记。

本地文件是唯一主数据源：

- 每篇思考以可直接阅读的 Markdown 正文和独立元数据保存；
- 回响、候选联系和交互事件使用独立结构化文件保存；
- 每次修改先写入一个完整的新数据代次并校验，成功后才切换当前指针；
- 旧代次、导入源文件和迁移快照不会被应用自动删除；
- 示例数据必须与私人数据分开，空目录不能自动写入示例日记；
- `local-data` 永远不进入 Git 提交和公开部署。

用户仍然可以主动导出和迁移：

- Markdown 导出：可选择多篇，包含标题、时间、来源、正文和标签，便于阅读与归档；
- 完整 JSON 副本：包含思考、图片、关联许可、思考线、回响和回响检查记录；
- JSON 导入：写入新的本地数据代次，恢复完整上下文；导入前的数据代次继续保留。

跨设备不再依赖 ChatGPT 账号自动同步。需要换电脑时，可以直接复制整个 `local-data` 文件夹，或使用完整 JSON 迁移。Markdown 只用于阅读和归档；未保存草稿仍是当前设备的临时状态，不属于正式日记数据。

如果用户主动使用 AI 回响或对话，获准参与回响的必要原文可能会发送给所配置的模型服务；本地存储不等于本地模型推理。系统必须明确区分“保存位置”和“模型处理位置”。
