## 范围边界：完成最重要的 80%

本期追求体验闭环和验证证据，不追求能力全面。

### 必须完成

- 关系延续中，用户写下 B 后，系统能够判断并保存 A + B 的候选联系；
- 时间延续中，系统能够用 A 的原句、时间和“为什么是现在”提出候选回响；
- 用户可以沿着两类回响继续写，并保存新的思考；
- 系统能追溯一次关系回响的 A、B、C，或一次时间回响的 A 与后续 B；
- 至少一个真实 good case 可以稳定演示；
- 至少一个 bad case 能说明 SOP 如何被修正；
- 作品集、视频、简历使用同一套真实材料。

### 本期不做

- 多模态知识库、思维导图或文件可视化；
- 知识图谱、向量数据库或复杂 RAG；
- 云端日记同步；
- 专属模型训练；
- 复杂意图识别 Agent；
- 高频主动提醒；
- 把 AI Chat 模拟包装成已经完成的真实能力。

## 回响 V1 用户旅程

```text
关系延续：写下 B → 判断 A + B 的未表达联系 → 展示两边证据 → 用户保存 C
时间延续：A 经过一段时间 → 说明为什么是现在 → 用户重新判断 → 保存 B
```

两条路径都遵守：保存时不弹出；一次只展示一个联系；不确定时保持空白；只有新思考保存后才记为成功。

### 回响卡必须包含

- 模式：关系延续或时间延续；
- 可核对的记录时间和真实原句；
- 关系延续展示 A、B 两边证据，时间延续说明“为什么是现在”；
- 一个能够继续思考的问题；
- “打开看看”；
- “继续写”；
- “这次没有联系”或“现在还不是时候”。

### V1 验收标准

- [ ] 引用原句真实率 100%；
- [ ] 关系延续 A、B、C 与时间延续 A、B 均可完整追溯；
- [ ] 保存 T2 时不立即打断用户；
- [ ] “这次无关”后不再展示；
- [ ] 只有保存新思考才记录为 `continuation_saved`；
- [ ] 完整 JSON 可以备份新增关系；
- [ ] 演示流程不需要临时修改数据或解释异常。

## AI Chat 模拟范围

### 路径 A：寻找过去的线索

用户带着当前问题进入 Chat。模拟体验返回：

- 一篇允许关联的旧思考；
- 时间和真实原句；
- 它与当前问题的关系；
- 一个轻量继续问题；
- 打开原文或继续写的入口。

### 路径 B：形成新的思考

当用户在对话中形成新判断时，Chat 只询问是否保存。AI 输出不会自动进入原料层；用户确认后才生成新的「我的思考」。

### 验收标准

- [ ] 两条路径都可以稳定演示；
- [ ] 明确显示引用来源；
- [ ] 模拟内容不会自动写入用户记忆；
- [ ] 作品集明确说明这是模拟体验。

## 案例验证方法

### Good case 标准

一个案例只有同时满足以下条件才可用于正式展示：

1. T1 提供了 T2 中没有的过去信息；
2. T1 有真实的判断、理由、条件或未完成问题；
3. T1 与 T2 之间存在明确变化量；
4. 关联不依赖关键词相同；
5. 用户看到后产生新的理解；
6. 最好能够继续写出 T3。

### Bad case 分类

| 类型 | 含义 |
|---|---|
| `keyword_only` | 只有关键词相同 |
| `invented_reason` | 系统替用户编造了原因 |
| `weak_delta` | 没有明确变化量 |
| `too_generic` | 旧记录过于宽泛 |
| `duplicate` | 与近期回响重复 |
| `bad_timing` | 关联成立，但当前不值得出现 |
| `no_next_step` | 看完不知道可以继续想什么 |
| `over_explained` | AI 解释过多，抢走用户思考 |

### 迭代规则

```text
发现 bad case
  → 标记一个主要错误类型
  → 只修改一条 SOP
  → 用已有 good case 做回归
  → 再测试新案例
```

不能为了修复一个 bad case，破坏已经成立的 good case。

## 作品集网页

作品集是产品案例研究，不是功能罗列。网页使用演示数据，不暴露私人日记。

### 内容结构

1. 用户问题；
2. 核心假设；
3. 为什么不做知识管理、多模态仓库和自动总结；
4. 关系延续 A + B → C 与时间延续 A + 现在 → B；
5. 原料层、记忆层、应用层；
6. 一个完整 good case；
7. 一个 bad case 及 SOP 迭代；
8. 15 篇真实思考的验证方法；
9. 当前结果和限制；
10. 个人贡献与反思。

### 验收标准

- [ ] V1 内容完整，可从头读懂产品；
- [ ] V2 视觉和移动端完成；
- [ ] 不展示私人日记；
- [ ] 不虚构用户数量、效果或模型能力；
- [ ] 发布为公开网页前单独确认访问权限。
