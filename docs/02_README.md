# 回页 · AI Diary

回页是一个本地优先的个人思考回看工具：保存用户亲自确认的日记，并在时间错位后，用可核验的原文帮助用户重新看见过去与当下的联系。

当前私人应用在本机运行，真实笔记只以项目中的 `local-data` 为主数据源。公开作品集将是独立的介绍与演示页面，不读取、不打包真实私人数据。

## 当前状态

- 本地应用可通过 `启动回页.cmd` 启动，默认地址为 `http://localhost:4317`；
- Windows 桌面快捷方式名称为“回页 · AI Diary”，与 `启动回页.cmd` 打开同一个本地应用；
- 当前有效基线为 15 篇真实 Entry、0 条旧 Echo；另有 2 条用于真实 case 校准的新 EchoRecord（1 条联系回响、1 条回看回响），尚无已验证延伸；
- 当前代码仍读写 `HuiyeBackup v1` 和不可变 generation；
- 目标模型已经确定为 `Entry + EchoRecord + CaseRecord`，思考线和拓扑由它们推导；
- 数据模型迁移尚未开始，现有 `local-data` 不能被覆盖或提交到 Git；
- 仓库中保留 Sites 项目配置和 `/portfolio` 骨架，但已经移除 R2 私人数据绑定，本轮没有重新部署。

## 核心原则

- 用户保存的原文是事实，AI 不能替用户补写动机、因果或人生结论；
- 保存是安静的，关系发现与回响展示必须错开；
- 只有回响后真正保存了新的 Entry，关系才进入已验证思考拓扑；
- 回页记录思考、理解和感受，不建设独立知识库；
- 本地存储不等于本地模型推理，未来接入远程模型时必须明确发送范围；
- 公开作品集只能使用脱敏演示数据。

## 用户路径

回页使用一个 BPMN 流程池和三条竖向泳道，固定从左到右为 `写作 → 日记池 → 回响`。圆形是开始或结束事件，圆角矩形是任务，带 `×` 的菱形是排他网关，双圆计时事件负责把候选发现与回响展示错开。所有顺序流只连接具体的小模块，并使用水平或垂直折线。

![回页用户路径 BPMN 2.0 流程图](D:/Codex/回页/docs/assets/huiye-user-path-bpmn.png)

[在浏览器中打开可缩放版本](http://localhost:4317/docs/assets/huiye-user-path.html)

上面的浏览器链接需要先启动本地回页。若要明确使用 Windows 默认浏览器，请在项目根目录双击 `打开用户路径图.cmd`；不要从 Markdown 预览器直接打开 `.html` 文件，因为该预览器只会显示源代码。

[下载可编辑的 BPMN 2.0 源文件](assets/huiye-user-path.bpmn)

浅灰任务属于规划能力：自动候选发现、质量判断、错位调度和“和 AI 聊聊”尚未完成；其余路径按当前保存、检索、回响卡片和事件记录能力绘制。

四条用户路径分别是：

1. `主动写作 → 确认保存 → Entry`；
2. `允许回响的 Entry → 候选质量判断 → 选择联系 / 回看回响 → 等待错位时间 → 回响卡片 → 没有感受，或继续写 → 新 Entry → 已验证关系 → 下一轮资格判断`；
3. `日记池 → 搜索 / 筛选 → 查看或编辑原文`；
4. `和 AI 聊聊 → 检索可引用 Entry → 回响卡片 → 继续写`。这条路径尚未开发，AI 对话内容也不会自动成为 Entry。

## 启动与检查

日常使用直接双击：

```text
启动回页.cmd
```

开发命令：

```powershell
npm run local
npm run local:verify
npm run local:verify-echoes
npm test
```

`npm run local:verify` 只校验当前本地数据；任何迁移都必须先制作可独立恢复的完整备份。

## 仓库边界

- `local-data/`、导入源、历史、事务日志和备份均属于私人数据，不进入 Git；
- GitHub 仓库只保存代码、测试、公开演示资产和文档；
- 不提交、不推送、不重新部署，除非用户明确授权对应操作。
