# 回页 · AI Diary

回页是一个本地优先的个人自我表达与跨时重逢工具。它保存用户亲自确认的思考、感受、疑问、生活片段和自己说出的话，并让这些内容在另一个时刻轻轻回来，与当下的用户再次发生关系。

回页的核心不是催促用户延续思考，也不是把 AI Chat 放在产品中心。AI 在幕后寻找、连接和初步理解那些本来会沉底的文字；用户可以沉默回味、回应一句、重新审视，也可以继续写一篇新的 Entry。

> 你写下的自己，不会在保存后必然沉没。它会在另一个时刻重新回到你面前。

当前私人应用在本机运行，真实内容只以项目中的 `local-data` 为主数据源。公开作品集是独立的介绍与演示页面，不读取、不打包真实私人数据。

## 当前状态

- 本地应用可通过 `启动回页.cmd` 启动，默认地址为 `http://localhost:4317`；
- 2026-08-05 最近一次磁盘校验为 23 篇真实 Entry、23 个唯一 ID、0 条旧 Echo；另有 2 条手工校准 EchoRecord；
- 当前 Entry 仍使用 v1 generation 存储，EchoRecord 已使用独立 JSON 文件；
- 当前卡片已经支持“原句 → 原文节选 → 完整全文”三级阅读；
- 产品方向已从“回响后必须延伸”调整为“重逢感优先，回应完全可选”；
- 自动候选发现、Prompt、调度、CaseRecord、双向连接和完整 v2 迁移尚未完成；
- 现有 `local-data` 不能被覆盖或提交到 Git。

## 核心原则

- Entry 保存用户确认的自我表达，不建设理论知识库或知识图谱；
- 用户原话是事实，AI 只能提出有证据、可修正的初步判断；
- 回响首先让用户重新看见自己，不要求产生洞见或新文字；
- 保存是安静的，关系发现与回响展示必须错开；
- 回响像陪伴而不是待办：不累计未读数，一次只呈现一个，不连续刷下一条；
- 用户明确保存的一句话回应也是新 Entry，并与来源 Entry 建立双向可读连接；
- `continuation_saved` 只是较深结果，不是回响成功的唯一标准；
- AI 的“懂我”来自反馈校准，温暖来自尊重边界；
- 本地存储不等于本地模型推理，未来远程分析只发送获得许可的最小必要原文。

## 用户路径

1. 用户写下并确认保存一段自我表达，形成 Entry；
2. 后台从允许回响的 Entry 中发现有证据的联系，或选择一次受约束的单页回看；
3. 候选经过质量、当前认知、时间、重复和冷却判断；
4. 合格候选不会形成未读队列，只通过回响入口的轻微提示表示“有一页在等你”；
5. 用户自愿打开后，先看原句、必要情境和完整原文，再看 AI 的解释性初判；
6. 用户可以直接离开，也可以给出可选反馈，或保存一句/一篇回应；
7. 保存回应后形成新 Entry，并与所有来源 Entry 建立双向可读连接；
8. 本次回响结束，不立即补上下一条。

## 仓库边界

- `local-data/`、导入源、历史、事务日志和备份均属于私人数据，不进入 Git；
- GitHub 仓库只保存代码、测试、公开演示资产和文档；
- 不提交、不推送、不重新部署，除非用户明确授权对应操作。
