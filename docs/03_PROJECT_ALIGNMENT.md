# 回页产品原则与 MVP 规格

> 状态：核心产品原则于 2026-08-08 对齐；线级 Context 评测实验于 2026-08-24 对齐。本页不把未来计划写成现状。

## 1. 核心定位

回页的唯一口号是：**让思考继续生长**。

回页不是“几个月后替用户总结变化”的回顾工具，也不是把思维过程外包给 AI 的自动知识图谱。用户拿回主动权：自己判断哪些记录在讨论同一件事，AI 在这个边界内显化用户已经隐约记录、但尚未清楚说出的延续、修正、分支、冲突或未解决问题。

思考的生长可以错位发生：今天看见联系，不代表今天必须写；新的理解也可能来自书、生活、他人和未记录的经历，而不是从旧日记线性推导出来。

## 2. 内容边界

回页保存思考、感受、疑问、判断、自己说出的话和生活片段。理论、事实、引文与图片可以作为情境出现，但纯知识管理与知识图谱交给外部工具。

是否归线是选择，不是保存门槛。未归线内容仍完整留在日记池；未来只在用户主动授权的一周或一月低频复盘中参与，不进入当前正式自动回响。

## 3. 思考线

- 是有稳定 ID 的一等对象，通过特殊视觉标签出现在 Entry 上；
- 一篇 Entry 可属于零条、一条或多条线；
- 只在 Entry 保存时创建新线，不允许空线；
- 三个归线入口：写下、日记池编辑、思考线详情批量加入；
- 支持移出、重命名、归档、恢复和合并；
- 合并保留来源状态，目标 AI 权限采用两侧中更保守的值；
- 当前只需要主线与交汇，不引入父子线、自动分支或网络图。

## 4. AI 与回响

回响本身就是 AI 观察，不另设一个用户可见的“分析”对象。正式候选必须：

1. 属于一条用户创建且允许 AI 的活跃思考线；
2. 引用至少两篇不同时间的 Entry；
3. 所有来源 Entry 都属于该线且单篇允许 AI；
4. 原文证据支持延续、修正、分支、冲突或未解决问题；
5. 不是历史 `legacy_evaluation` 或已失效记录。

AI 先展示用户原文，再给出“暂时看见、由你判断”的初判。每篇来源默认呈现原句与已展开的原文节选，用户可收起；完整原文仍需主动展开。评测工作台与正式回响使用相同初始状态。AI 不能把候选宣布为人生结论，不能用情绪浓度冒充价值，也不能越过思考线自动做跨领域全量审视。

## 5. 成功标准

回响的第一质量是 **显化价值**：用户是否因为这次观察，更清楚地看见自己正在怎样思考。重逢感是第二质量：用户是否重新遇见了当时的自己。

反馈为：

- `看清了一点`：AI 让隐约记录的东西更清楚；
- `我已经知道了`：判断可能正确，但没有新增显化；
- `不太对`：证据、关系或解释存在偏差。

沉默保持未知。用户不需要回应；若保存回应，它作为 EchoReply 直接留在回响下方，可编辑、可删除，不进入日记池，也不自动参与未来回响。回应与三类反馈相互独立，任一动作都不能推断另一动作。

## 6. 陪伴式呈现

回响入口用轻微的小棕点表示有一条观察可看，不弹窗、不计未读数、不形成待清空队列。看过的回响留在思考线时间线上：打开未反馈为空心点，看清为强调实点，已知为弱化点，不太对为淡化历史且不再代表有效连接。

## 7. 权限

- 单篇关闭：AI 在任何所属思考线中都跳过该 Entry；
- 整线关闭：该线不产生新的正式回响；
- 单篇拒绝优先于整线允许；
- 多线交汇不自动授权跨线分析；
- 公开展示模式不读取私人日记。

## 8. MVP 验收

第一版必须完成：思考线三入口、详情时间线、生命周期与双重权限、线内正式回响筛选、线上回响点、三类反馈、评测/展示隔离、本地兼容存储、核心文档与测试。

长文书写体验同样属于第一版验收：写下页与日记池正文按渲染后的视觉行计数，前 15 行完整展开，第 16 行起在纸张内部即时、最小距离跟随光标，并在光标下方保留约 4 行舒适区。连续回车不得让内部滚动反向。写下页持续输入时外层页面按视觉行自然向下，使顶部标语离开视野；用户主动向上回看时保持原位，到下一次输入才重新找到光标。日记池固定编辑面板不得带动背景页面。

第一版明确不做：生产模型调用、prompt 编辑器、自动归线、全局网络图、父子思考线、自动跨线分析、正式低频全库复盘、AI Chat 调用思考线。

## 9. 公开展示边界

公开作品集、PortfolioMode 与私人本地回页是三种不同入口：作品集负责解释产品价值、个人贡献与验证过程；PortfolioMode 使用经用户逐项审核的 MinimumRedaction 固定数据供访客操作；私人本地回页只在本机读取 `local-data/`。简历网址不能落入私人空白模式，公开演示也不能尝试读取私人数据。桌面快捷方式继续直接进入私人本地回页，不改变日常使用习惯。

公开作品集采用“证据型项目档案”而非宣传页结构：首屏同时提供项目说明、产品体验和完整评测入口，随后依次用真实脱敏笔记解释产品核心、展示用户流程图、用真实 good / bad Case 说明评测迭代，最后交代工程交付。展示材料必须让原文、AI 观察和用户反馈承担证明作用，不能只用抽象口号代替证据。

## 10. 回响评测阶段

评测体系按“场景输入 → 预期输出 → 模型能力与上下文 → 上下文模块与动作框架”拆解，再对 bad case 做归因。一次完整评测最终需要评测集、参考答案、模型输出集和评测标准。

当前仍处于 good case 探索期：已有真实输入、候选模型输出和人工反馈，但尚无稳定参考答案。因此本阶段不能把第一批输出冒充标准答案，而应先找到真正具有显化价值的 good case，再反推参考答案、能力要求、上下文供给和完整归因标准。结构化反馈只评价 AI 观察质量；good/bad 是独立的评测判断，用户原话另行逐字保存。

### 10.1 线级 Context 评测实验

线级 Context 实验的产品行为不是把所有两两 Entry 组合交给模型，而是先维护整条线的宏观认识，再按索引回看少量原文：

1. EntryCard Agent 为每篇允许 AI 的 Entry 建立跨 ThoughtLine 共用的不可变 CardVersion；每条线的完整引用章节由代码维护，所有合格 Entry 恰好出现一次；
2. ThoughtLineContext Agent 只维护 discusses、majorConcerns、thoughtStages、stableView、currentFocus、tensions 六个宏观章节，不保存 A→B 等具体关系、关系类型或核验状态；
3. ContextMaintenance Agent 接收 Entry 增量、Prompt 变化或单次 Echo 的 `not_quite` 反馈，判断宏观 Context 保持不变、局部修订或全量重建；来源变化后受影响线先进入 `stale`，完整新快照发布后才恢复 `ready`；
4. 同一个 RelationJudgment Agent 使用同一份 Prompt：先读取全部 `ready` Context，一次给出零至三个两至三篇的有序候选；规则门禁通过后，候选判断继续携带导航时同一份所选线 ContextSnapshot 投影，并读取候选原文与历史状态。Context 只检查完整性、必要中间 Entry 与解释风险，不作为证据；首个输出立即停止，全部放弃则沉默；
5. ContextModule 与 RelationModule 是两个深模块；正式产品调度不调用该实验链路，显式开发评测可接 Fake 或真实 Agent Adapter，RelationModule 自身只返回内存草稿。

一次性 B/C 配对评测是上述结构之外的历史诊断实验：候选选择只执行一次，B 仅依赖结构化 `navigationBasis`、候选原文与冻结历史；C 额外读取所选线的宏观 ContextSnapshot。产品负责人已选择 C 作为当前实验方案，因此 canonical RelationJudgment 使用 C 的上下文连续性边界；旧 B/C 结果保留为可追溯实验数据，不再作为开发评测工作台的当前并列方案。该选择仍不等于质量已验证或可以接入生产。

本地只保留一个 EvaluationWorkbench，一级类别为 Context 与回响：Context 复用现有快照、EntryCards、历史 Diff 和 Prompt 展示，不增加评分；回响保存并展开每次评测的完整 Agent trace、候选与规则门禁、最终测试回响或沉默、既有人工评测和历史 B/C。运行产物只写评测目录并直接渲染测试回响卡片，不写 `local-data/echoes`，也不改变正式回响资格或历史。

这个实验保留 ThoughtLine 权限边界：交汇 Entry 可以显示全部思考线身份，但不能借交汇点读取其他线 Entry。它也保留沉默、两篇默认而三篇只补足必要断层、原文证据与解释风险门槛。`echo-eval-v0.4` 及更早 Echo Prompt 只作为冻结评测基线，不是新版 RelationModule 的调用路径，也不被描述为已经替换；只有完成 Context 与最终回响两层真实 Case 对比后，才决定是否接真实模型、继续调整或停用新模块。

评测界面采用 EvaluationWorkbook：顶部始终显示可横向浏览的评测总表，点击一行后只展开该 Case 的完整证据与反馈；“评测标准” Sheet 保存当前维度尺度，“Prompt 版本” Sheet 保存每版全文、状态、变更原因、评测依据和继承关系。来源 Entry 在详情卡中纵向排列，右上角展示其涉及的一条或多条 ThoughtLine。

首批 EvaluationDimension 为关系成立度、显化增量和重逢感，分别使用高／中／低。good/bad 仍由人最终判断，不由维度机械求和：关系成立度为低时原则上是 bad；关系成立但另外两项都低时通常也是 bad。首批批量 Case 冻结使用 `echo-eval-v0.1`；`v0.2` 仅将关系类型输出改为中文并继承 v0.1 评测，不冒充独立模型运行。`echo-eval-v0.3` 从“判断预选 Entry”升级为“在调用方授权的一条主 ThoughtLine 内搜索”：单次只返回一个最值得呈现的最小充分来源集，或在内部保持沉默；它已用一条新候选完成首轮人工验证，结果为 good，三个评测维度均为高。当前待评测版本 `echo-eval-v0.4` 继承该语义门槛，并增加确定性的来源复用门禁：规则引擎计算已有使用次数和排除组合，LLM 只判断真实关系及强烈变化例外；本次使任一 Entry 达到第三次使用时默认放弃，只有强烈变化、旧来源不可替代、非复述同时成立才破例。每条线最多三轮候选搜索，被拒组合加入本轮排除集；各线最多保留一条候选，再跨线选择综合最稳的一条，否则保持沉默。交汇 Entry 可以披露其他 ThoughtLine 身份，但不扩大搜索边界。正式界面不展示放弃结果，评测过程保留无真实关系、证据不足、无显化增量、解释风险过高和来源过度复用等原因。Prompt 内容变化才升级版本，输入数量、时间跨度和思考线变化不升级；EchoRecord 内部关系枚举继续使用英文，已有 Case 不追溯改写。
