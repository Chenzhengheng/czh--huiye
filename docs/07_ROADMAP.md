## P1：用真实 case 验证回响

### 联系回响（长期约 80%）

- [ ] 从允许回响的 Entry 中发现有原文证据的候选关系；
- [ ] 关系通过质量门槛后才创建 EchoRecord；
- [ ] 发现和展示分离，禁止保存后立即弹出；
- [x] 分别展示 A、B 的原文片段、单句 AI 浓缩和时间戳；
- [x] 在底部展示一处有证据的不同、变化或感受线索，并只提出一个问题；
- [x] 原文采用三级展开，节选边缘有轻微动效，并支持减少动态效果；
- [x] 只有保存 C 才写入 `continuation_saved`；
- [ ] 从 EchoRecord 推导候选拓扑与已验证拓扑。

### 回看回响（长期约 20%）

- [ ] 实现 allowEcho、时间间隔、近期重复、拒绝和冷却期约束；
- [ ] 在合格集合中随机选择，不虚构“为什么今天出现”；
- [ ] 保存当下的新感受后形成已验证关系。

### good case / bad case

- [ ] CaseRecord 只引用 Entry、EchoRecord 和可选分析 Entry；
- [ ] 记录预期、实际、原因标签和规则版本；
- [ ] 用户保存的案例分析作为普通 Entry 参与未来拓扑；
- [ ] 用 case 迭代质量门槛、时机和提问方式，而不是追求回响数量。

## P2：公开作品集

- [ ] 将私人 LocalApp 与公开 PortfolioSite 建立清晰构建边界；
- [ ] 作品集只使用脱敏、人工确认的演示数据；
- [ ] 构建时检测并拒绝任何 `local-data` 或真实日记内容；
- [ ] 展示产品问题、两种回响、数据模型、good/bad case 和迭代结论；
- [ ] 提供 GitHub 链接及必要的界面演示；
- [ ] 由用户明确确认后才提交、推送或发布。

## 暂不做

- 多用户、社交或公开社区；
- 跨设备自动同步和冲突合并；
- 人格分析、心理诊断或自动人生总结；
- 独立知识库或知识图谱；
- 为了数量而高频推送回响；
- 专属模型训练；
- 在 v2 数据迁移验收前清理唯一可恢复的旧数据。

## v2 数据阶段完成标准

以下条件全部满足才算完成：

1. 迁移前备份经过独立恢复验证；
2. 新旧 Entry 数量、ID、正文哈希和附件完全一致；
3. 旧 Echo 和旧检查标记不进入 v2；
4. 新写、编辑、异常中断、恢复、软删除和永久删除测试通过；
5. 应用重启后仍从同一批本地文件读取；
6. `local-data` 没有进入 Git 或作品集构建；
7. 用户亲自打开应用并确认 15 篇基线数据和新增笔记正常。
