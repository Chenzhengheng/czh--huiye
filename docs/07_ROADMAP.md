## 下一步：案例校准

用真实笔记重新归线；高频生成候选但不打扰正式体验；分别记录“看清 / 已知 / 不太对”、用户原话与 good/bad 判断；从 case 反推候选条件、原文证据、时机和 Prompt；之后再决定生产模型和出现频率。

评测集尚未建立参考答案。先用不超过 15 条的阅读型卡片寻找 good case；规模继续增长后使用表格总览与单条展开，再逐步补齐参考答案和可归因的评测标准。

## 随后可能做

用户主动启动回响；周/月级授权的未归线与跨线复盘；在 AI 聊聊中调用思考线；连接足够多后探索主线、分支和交汇网络。

## 暂不做

自动归线、父子线、实时全库扫描、随机单页正式召回、生产 Prompt 编辑器、知识库、未读队列、强制回应、自动跨线人格分析。

## 下一工作日从这里开始（预计 2–3 小时）

1. 基于现有真实日记与人为思考线批量生成候选回响，扩充 good / bad case；Case 01 作为首个已收口样本保留。
2. 从批量 case 反推并收敛联系标准、回响质量标准、失败归因和通用 Prompt 所需上下文。
3. 准备作品集网页：演示回页当前完整功能，使用脱敏且不含敏感内容的真实笔记 case 与评测集，并展示 GitHub 仓库入口和用户流程图。
4. 基于已验证的产品问题、AI 角色、个人贡献与评测方法，整理项目简历表述。

作品集目前只记录为计划目标，不代表已经实现或已经公开私有本地数据。
