# 回页：AI 整理标准

> 历史文档：本文服务于已经退出当前产品主线的 AI 整理方案，不代表现行产品设计。当前每篇记录只保留一份用户确认的「我的思考」。保留本文仅用于理解遗留 `/api/organize`、旧 Prompt 和历史验收标准。

> 原用途：这是“回页”AI 整理方案的产品基准、提示词规范与人工验收样例。过去调整模型或 prompt 时，以它为准。

## 1. 一句话目标

AI 不替用户想得更完整；它只让用户未来更容易重新进入自己已经写下的思考。

**最小整理不是原样复写。** 在不增加观点、不改变逻辑的前提下，AI 应识别原文已有的结构，并为它留出呼吸。

## 2. 必须遵守的边界

- 用户原文是唯一事实来源；不得补充事实、动机、因果、案例、结论或建议。
- 保留原有的语气、推理顺序、犹豫、括号、限定、跳跃和自我保留。
- 不做心理分析、人格判断、价值评判、鼓励或温情化表达。
- 原文、整理稿、标题与标签是独立字段；AI 产物绝不静默覆盖原文。
- 正文字段只能放可直接接受的正文，不能混入“建议标题”“最小整理稿”“标签”“注”等字段说明或解释。

## 3. 什么是“有呼吸的克制整理”

允许的动作：

1. 在原文已有的转折、举例、拆解、并列项或推理阶段之间分段、留白。
2. 把用户明确写出的“第一、第二、第三”等并列项改为列表。
3. 把原文已有的“举例”“再往下拆解”等词单独成行，作为阅读锚点。
4. 修正明显的错别字、标点或断句。

不允许的动作：

- 创造“总结”“核心结论”“启示”等概念性小标题；
- 为了看起来完整而补齐论证；
- 把“这里我瞎说的”这类保留意见修改为确定判断；
- 只做机械换行，或反过来把用户的段落压成一团。

## 4. 标题与标签

### 标题

标题应指出这篇记录的真实张力、问题或推理路径，而不是机械并列两个名词。不能找到贴切标题时，宁可保留原有标题或使用“未命名记录”。

### 标签

标签是未来检索的路标，而不是从原文抽出的零散短语。给 1–3 个来自原文、具体且可辨认的概念；不确定时宁可少给。

## 5. 验收样例

### 原文的核心片段

> 一句浓缩的话确实能表达出最精华的部分，但是你只读这句话，你是完全用不出来的，第一，不知道其产生的背景，第二，不知道适用的边界条件，第三，不知道做到什么程度。
>
> 举例：做产品要差异化，因为要和别人的产品显得不同。这个并不是深层原因，我认为“不同”深层原因是稀缺性。再往下拆解……（这里我瞎说的）。

### 期望整理形态

**建议标题：** 精华为什么不能脱离它的背景与边界？

一句浓缩的话确实能表达出最精华的部分，但是只读这句话，你完全用不出来：

- 不知道其产生的背景；
- 不知道适用的边界条件；
- 不知道做到什么程度。

举例

做产品要差异化，因为要和别人的产品显得不同。这个并不是深层原因，我认为“不同”背后的深层原因是稀缺性。

再往下拆解

保留原文的推理、限定与“这里我瞎说的”。

**标签：** 阅读方法、产品差异化、稀缺性

这个样例的重点不是措辞本身，而是：不替用户加结论，只把原文已有的结构和停顿显露出来。

## 6. 当前系统提示词的执行要求

系统提示词应同时包含：

- 上述边界与“有呼吸的克制整理”标准；
- 固定 JSON 输出：`title`、`organized_content`、`tags`；
- 字段隔离要求：正文绝不携带标题、标签、注释或解释；
- 用户可编辑的个性化 prompt，但不得覆盖产品级的字段边界与原文保护规则。

## 7. 样例库与回归测试

人工认可的完整样例统一收录在 [AI_ORGANIZATION_EXAMPLES.md](AI_ORGANIZATION_EXAMPLES.md)。调 prompt 或换模型时，必须用它们逐篇对照：是否保留原意、是否有阅读呼吸、标题和标签是否可用、是否出现越界补充。
